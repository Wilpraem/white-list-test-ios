# Проверка белых списков (White List Test)

React Native / Expo приложение для фоновой и ручной проверки доступности веб-ресурсов (выявление "белых списков" при блокировках мобильного интернета).

## Технологический стек
- **Фреймворк:** React Native 0.81.5 + Expo SDK 54
- **Язык:** TypeScript
- **Навигация:** Expo Router
- **Ключевые пакеты:** `expo-background-fetch`, `expo-task-manager`, `react-native-vpn-detector`

---

## 💻 Локальный запуск (Mac M1/M2/M3)

### Требования
1. Установленный **Node.js** (рекомендуется v20+)
2. **Xcode** (загружается из Mac App Store) для iOS-разработки
3. Установленный **CocoaPods** (для ручной сборки iOS, если требуется)

### Установка зависимостей
```bash
npm install
```

### 🍎 Запуск на iOS (Симулятор)
Самый простой способ — использовать встроенную команду Expo, которая сама сгенерирует нативный код и установит Pods:
```bash
# Команда соберет проект и откроет iOS Simulator
npm run ios
# или
npx expo run:ios
```
*(При первом запуске скачивание движка Hermes и зависимостей может занять от 2 до 10 минут. Это нормально, просто подождите).*

### 📱 Запуск на реальном iPhone (через кабель)
1. Сгенерируйте iOS-проект (если папки `ios` еще нет):
   ```bash
   npx expo prebuild --platform ios --clean
   ```
2. Откройте проект в Xcode:
   ```bash
   xed ios
   ```
3. В левой панели Xcode выберите корневой проект `testwhitelist`.
4. Перейдите во вкладку **Signing & Capabilities**.
5. В поле **Team** выберите свой аккаунт Apple ID (можно добавить в `Xcode -> Settings -> Accounts`).
6. Убедитесь, что `Bundle Identifier` уникален (сейчас `com.zvezda4443.testwhitelist`).
7. Подключите iPhone кабелем, выберите его в верхней панели Xcode (вместо симулятора) и нажмите **Play** (`Cmd + R`).

## 🚀 Сборка и релиз через Expo Application Services (EAS)

Для облачной сборки (TestFlight, App Store, Google Play) используется EAS Build.

### Подготовка
1. Установите EAS CLI:
   ```bash
   npm install -g eas-cli
   ```
2. Авторизуйтесь в свой Expo аккаунт:
   ```bash
   eas login
   ```

### Сборка для iOS (TestFlight / App Store)
```bash
eas build --platform ios --profile production
```
*Скрипт попросит вас войти в Apple Developer аккаунт для генерации сертификатов и профилей. После сборки вы можете отправить билд в TestFlight командой:*
```bash
eas submit -p ios
```

### Сборка для Android (APK / AAB)
Для внутреннего тестирования (APK-файл):
```bash
eas build --platform android --profile preview
```
Для Google Play (AAB-файл):
```bash
eas build --platform android --profile production
```

## ⚠️ Важные ограничения iOS

Так как приложение использует фоновые задачи (`expo-background-fetch`), обратите внимание на специфику платформы Apple:
1. **Непредсказуемость Background Fetch**: В отличие от Android, на iOS интервал в `5 минут` — это лишь "пожелание". iOS сама решает (на основе машинного обучения и того, как часто пользователь открывает приложение), когда дать приложению проснуться в фоне.
2. **Лимит времени**: При пробуждении в фоне на iOS у приложения есть **всего ~30 секунд** на выполнение задачи. Текущая реализация (пинг 3-х сайтов) легко укладывается в этот лимит.
3. **Нет Foreground Service**: На Android фоновую работу можно сделать непрерывной с помощью "закрепленного" уведомления (Foreground Service). На iOS такого механизма нет (он разрешен только для музыки, навигаторов и VoIP), поэтому полагаемся только на периодический Background Fetch.
4. **Перезагрузка устройства**: Опция автозапуска после включения телефона (`startOnBoot: true`) работает только на Android. На iOS пользователь должен запустить приложение вручную хотя бы один раз после перезагрузки.
